# コンテナ

```
+-Devcontainer-(DinD)---------------+
| Docker操作スクリプト              |
| bootstrapスクリプト               |
| git操作                           |
| +-開発用コンテナ--------------+   |
| | 開発用ツールチェーン        |   |
| | ビルドツールチェーン        |   |
| |  +--------------------------|-+ |
| |  | 共有ボリューム(src)      | | |
| +-----------------------------+ | |
|    | デプロイツールチェーン     | |
|    | クレデンシャル(環境変数)   | |
|    +-|--------デプロイコンテナ--+ |
|      クレデンシャル(.env)         |
+-----------------------------------+
```

セキュリティ上の理由から, 開発用コンテナ と デプロイ用コンテナ を分離する.


開発/ビルド用のコンテナでは, 

- 依存関係の解決
- 静的アセットなどのビルド
- 開発時に使用するツールの実行

などのクレデンシャルを要しない作業を行う.


デプロイ用コンテナでは, デプロイやpushなどのクレデンシャルを要する作業を行う.
npmパッケージで多発する攻撃への対策のため, 最低限の作業に留めること.

> [!NOTE]
> Dockerの操作スクリプトは, Devcontainerの内部で動作させれば, ホストOSによらずに使用可能.
> DevcontainerはDockerの操作のためだけに用意してあるので, 必ずしも利用しなければならないわけではない.
>
> 特に, src内の各プロジェクトを開発用コンテナに接続したエディタで開きたい場合は, 
> ホストで`docker-compose up -d`を実行して, 
> ホストのDockerに直接開発用コンテナを配置したほうが良い.

## コンテナへの接続

`docker-compose up`でコンテナを立ち上げ, `docker-compose exec`でシェルを起動すれば接続できます.
複雑な作業ではありませんが, 一応`./stepin.sh`を用意しています.

`./stepin.sh`を実行すれば対話的に接続のための案内が表示されます.

# リソースの追加

workerの分割を前提とする.
workerを分割しない場合は, Next.jsのようなフルスタックフレームワークが有用な選択肢となるが,
backend/frontendでのworkerの分離を前提とする場合, Next.jsはよい選択肢ではない.

backend workerなら, 
```
[dev] npm create cloudflare@latest
```
でhonoフレームワークを選択することを奨める.

frontendなら, 
```
[dev] npm create vite@latest
```
でframework: React/router: TanStack Router/deploy: Cloudflareを選択することを奨める.

# local web serverの立ち上げ

動作確認のためにローカル向けのWeb Serverを立ち上げたい場面は多々あります.

コンテナを使わない場合は, 特に注意点はなく, `npm run dev`で十分なのですが, 
開発用コンテナ内でWeb Serverを立ち上げる場合, 

1. 開発用コンテナで**ポートフォワード**の設定をする必要があります.
2. Dev Containerを使用している場合, Dev Containerでもポートフォワードを設定する必要があります.
3. **WebServerのホストアドレスを指定**する必要があります.

1. Dockerコンテナは, 設定しなければリクエストをフォワード (リクエストをコンテナ内に取り込み) しません.
そのため, そのままではリクエストがServerに届きません.

この問題を解消するために, ポートフォワードの設定をします. 
`docker-compose.yml`のportフィールドに, フォワードしたいリクエストの種類(ポート番号)を書きます.

`[コンテナが見張るリクエストの宛先アドレス]:[コンテナが見張る外側のポート番号]:[コンテナの中に渡すときのポート番号]`

というフォーマットです.

```yml
  dev:
   ...
    ports:
      # 外側で127.0.0.1(localhost)あての3000番へのリクエストを監視して, 
      # リクエストがあればコンテナの中に3000番のリクエストとして受け渡す.
      - "127.0.0.1:3000:3000"
      - "127.0.0.1:8787:8787"
```

2. Dev Containerを使用している場合, 1と同種の問題が発生します. 
local serverの起動を感知してよしなに設定してくれる機能もありますが, DinD環境では期待できなさそうです.

`docker-compose.yml`で開発用コンテナの設定したように, `.devcontainer/devcontainer.json`でDev Containerの設定をします.
"forwardPorts"というフィールドがあるので, ここにポート番号を書けばOKです.

```jsonc
	"forwardPorts": [
		3000, // (外側で見るべきポートも内側のポートも3000番)
		8787
	],
```

内側に取り込まれたリクエストはそのまま開発用コンテナに受け渡されるのではなく, 
DevContainer Serverという, Dev Container内部のプロセスが, 
仲介者として間にはいることで, 外からのリクエストをlocalhostあてのリクエストに変換されます.

そのため, 127.0.0.1(localhost)をlistenしている開発用コンテナにリクエストが届きます.

3. *ホストアドレスを指定しない場合*は, Web Serverはlocalhostへのリクエストをlistenします.
どういうことかというと, リクエストが届いたとしても, **開発用コンテナ内部からのリクエスト以外は無視する**ということです.
*ホスト(コンピュータ)からコンテナ内*のWebServerにアクセスするためには, ホストアドレスを`0.0.0.0`とします.
ホストアドレスを`0.0.0.0`に設定することは, **どんな**アドレスに対する**リクエストも**, 手元に届けば取り**扱う**ように設定することです.



```
+-- host --[NC](172.*.*.*)-------------------------------------------+
|           |  [lo] <- browser etc.                                  | <-+
|           x   |:3000                                               |   |
|        on localhost:3000 -> devcontainer(:3000)                    |   | Dev Containerで設定する
| +--devcontainer--------------------------[VNC](172.*.*.*)--------+ |   |
| |                                          |:3000                | |   |
| |        [lo](172.0.0.1) <- (agent) <- on VNC                    | |   |
| |          |:3000                                                | | <-+
| |          |                                                     | | <-+
| |       on localhost:3000 -> dev(:3000)                          | |   | Docker (in Docker)で設定する
| | +-dev----------[VNC](172.*.*.*)------------------------------+ | |   |
| | |                |:3000                                      | | | <-+
| | |                |   +--[lo] <- curl etc.                    | | |
| | |                |   |:3000                                  | | |
| | |                |   |                                       | | |
| | |                +-----------+                               | | |
| | |                |   |       |                               | | |
| | |                |   +---+   |                               | | |
| | |                |   |   |   x                               | | | <-+
| | |                |   | on localost:3000 -> WebServer         | | |   |
| | |                |   |                                       | | |   | Web Serverで設定する
| | |            on 0.0.0.0:3000 -> WebServer                    | | |   |
| | +------------------------------------------------------------+ | | <-+
| +----------------------------------------------------------------+ |
+--------------------------------------------------------------------+
```

API Serverについても, Web Serverと同様の対処が必要です.
API Serverへのリクエストは, Web Serverではなくブラウザが発行するものだからです.
```
[Web Server]      [API Server]     コンテナの壁    [ブラウザ]
      |                 |              | |             |
      |<-------------------リクエスト------------------+ アクセス
      |                 |              | |             |
      |  Webページ      |              | |             |
      +--frontendソース------------------------------->| 表示, 実行
      |                 |              | |             |
      .                 |              | |             |
                        |<-----------------------------+ APIリクエスト (in frontend)
                        |              | |             |
                        .              | |             .
```
